## 存档面板修复（Web / Windows / Android）

这次修的是「存档按钮能点，但面板里什么都点不了 / 面板是空的」这一组问题，
根因分布在网页、Android 原生触控层和静态文件部署三处。

### Web：存档终于按游戏版本读写

- nginx 注入顺序是「先同步执行 sync.js，再 defer 执行 version-check.js」，
  所以 sync.js 一直读不到游戏版本，Web 端所有请求都不带 `gameVersion`，
  进度全写进 legacy 分区；带版本的客户端自然对不上。
  现在 sync.js 会从页面标题（`PvZ2 Gardendless Online | 0.16.1`）兜底解析，
  并把版本回填给同源的管理页/冲突页。
- 冲突页（`/_save/conflict.html`）现在按 `gameVersion` 读取、上传和覆盖，
  不再把当前版本的存档写进 legacy。
- 冲突页新增「下载云端存档（JSON）」：先下载留档，再决定用哪一份；
  下载只读，不会改动本机进度。
- 云端当前版本没有存档时，下载/「使用云端」会明确禁用并说明原因，
  不再出现「只能点本机」的无声状态。
- 管理页的「上传本机存档」现在写当前游戏版本（Web 面板 iframe 同源，
  会读父页面的版本），并在确认框里写明目标版本；上传带并发基准版本。

### Web / App：入口收口

- 游戏内右下角只保留「存档」入口，打开的是和网页端一致的存档管理页。
- 删除独立的「↑ 上传」悬浮按钮；手动上传只在存档管理界面内部提供。
- 普通用户也能打开面板，只能看到自己的云端存档、历史版本与回滚；
  跨用户管理仍然只给管理员。

### Android：面板按钮不再被原生触控层吃掉

- 原生 `touch_input_adapter.js` 会在 document 捕获阶段对所有触摸
  `preventDefault`，把触摸翻译成 Cocos 的鼠标事件。副作用是注入的
  DOM 控件永远收不到 `click`：只有自己处理 `pointerup` 的「存档」FAB
  看起来能点，顶部提示条的按钮、面板关闭按钮、下载按钮全部失效。
- 触控适配器现在把带 `data-pvz-ui` 的存档面板 DOM 当作原生控件放行；
  面板脚本也在 window 捕获阶段保护自身（旧版 APK 同样生效）。
- 面板 iframe 改用配置里的服务器绝对地址：离线资源包 / 桌面端页面
  origin 是 `appassets` 或 `127.0.0.1`，原来的相对路径会 404，面板只剩
  一块空底色。现在 Android 本地/在线与 Windows 都能加载管理页。

### 验证

- 服务端 201 项、客户端 191 项，合计 **392 项全绿**；
  Android JVM 视口单测 4 项通过。
- `test-cloud-saves.sh` 连续 3 次 97/0；修复了 `printf | grep -q` 在
  `pipefail` 下随机 SIGPIPE 造成的假失败（实测 200 次里 186 次误报）。
- 真实 Chrome 验证：冲突页按 v0.16.1 读取/下载/覆盖/上传；
  Web 面板普通用户可见、无独立上传按钮、手动上传写 v0.16.1；
  App 面板在模拟原生触控捕获层下，冲突条按钮、关闭按钮、iframe 内按钮
  都可点击。
- 服务端静态文件由 `tools/deploy-static.sh` 统一生成/部署，`--check`
  能挡住「源码改了、/var/www 还是旧副本」的漂移。
